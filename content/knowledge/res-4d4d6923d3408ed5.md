把知识按依赖关系组织，可以减少反复学习同一个概念的成本。先建立语言、浏览器与网络的共同基础，再进入框架和工程实践。

## 一张知识地图

```text
Web 开发
├── 语言：HTML / CSS / JavaScript / TypeScript
├── 运行环境：DOM / 事件循环 / 渲染 / 存储
├── 网络：HTTP / HTTPS / 缓存 / 跨域 / 实时通信
├── 框架：组件 / 状态 / 副作用 / 路由
├── 工程：依赖 / 构建 / 测试 / 部署 / 可观测性
└── AI 应用：检索 / 工具调用 / MCP / Agent 执行环境
```

## 按问题推进

第一轮先回答“它解决什么问题”，用一句话描述概念，再写最小可运行的例子。第二轮关注边界：什么情况下不适用、失败时怎么处理。第三轮把相邻知识连接起来，例如从 HTTP 缓存连接到 CDN 和部署策略。

每次学习保留三个产物：一个自己的解释、一个可以运行的例子、一个仍需验证的问题。不要把看过文章的数量当成已经掌握的数量。

## 复习节奏

每天选择少量知识点加入计划，先复述昨天的内容，再学习新问题。每周用一个小功能串联知识，例如带搜索与缓存的列表页。遇到无法解释的行为，再回到对应章节。

在题库中收藏需要复习的内容；能独立解释并写出例子后标记掌握。笔记记录自己的判断、实验结果和出错原因，比只摘录结论更容易复习。

## 面试复盘模板

```markdown
## 日期与岗位

## 遇到的问题

## 我当时的回答

## 缺少的证据或边界

## 补做的实验

## 下次如何回答
```

按日期保留每次复盘，再归纳反复出现的薄弱点。面经的题目范围只代表对应样本，不能推断所有公司的固定考点或频率。
