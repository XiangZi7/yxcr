依赖声明描述允许使用的版本范围，锁文件记录一次解析得到的具体依赖图。把两者一起维护，才能让开发机和构建环境使用一致的依赖。

## install 与 ci

日常增加或更新依赖使用 `npm install`，并检查锁文件变化。持续集成中使用 `npm ci`：它要求存在锁文件，在声明与锁文件不一致时失败，不会替你更新锁文件。

```shell
# 日常开发
npm install

# 在提交中保留 package.json 和 package-lock.json
# 持续集成
npm ci
npm run build
```

`npm ci` 会先移除已有的 `node_modules` 再安装。不要把它当成保留当前依赖目录的增量操作。

## 项目约定

一个项目统一使用一种包管理器及对应锁文件。在 `packageManager` 中记录版本，避免不同工具反复生成互不一致的依赖图。使用 pnpm 的项目，应按该项目的 pnpm 版本与锁文件约定安装。

## 排查安装失败

先读清楚错误属于网络、版本冲突、平台二进制还是生命周期脚本。先检查 Node 与包管理器版本，再检查锁文件是否同步。不要每次失败都删除锁文件，这会引入与当前问题无关的版本变化。

依据：[npm ci 官方文档](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。
